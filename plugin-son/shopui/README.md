# ShopUI — 虚拟旅商商店

**手持锡斧挥动** → 在脚底召唤一个**仅自己可见**的虚拟旅商；再次挥动拉回身边；关闭对话或下线自动消失。
后续将扩展旅商商店定制与**商店物品触发器**。

## 交互

| 操作 | 效果 |
|------|------|
| 手持**锡斧**按下使用键（挥动） | 召唤虚拟旅商（仅自己可见，站定在脚底） |
| 旅商存在时**再次挥动锡斧** | 把旅商拉回身边 |
| 点击旅商对话 → 关闭对话 | 旅商自动消失 |
| 直接下线 | 自动清理 |

> 检测的是"挥动"（按下使用键的瞬间），不是"手持"——平时拿着锡斧不会触发，只有挥动才触发。
> 挥动判定：`PlayerUpdate` 包中 `IsUsingItem` 上升沿 + 手持槽位物品为锡斧（`ItemID.TinAxe=3500`）。

## 命令（调试辅助）

| 命令 | 权限 | 说明 |
|------|------|------|
| `/shopui` | 无 | 等价于一次挥动（召唤/拉回） |
| `/shopui kill` | 无 | 立即移除自己的虚拟旅商 |
| `/shopui status` | 无 | 查看当前激活的虚拟旅商数量 |

## 构建

```bash
cd plugin-son/shopui
dotnet build -c Release
```

产物：`bin/Release/net9.0/shopui.dll`，放入 TShock 的 `ServerPlugins/` 目录。

## 验证步骤

1. 手持锡斧，在空旷处挥动（左键）
2. 预期：脚底出现旅商（**其他玩家看不到**），服务器日志
   `[ShopUI] 玩家 xxx 召唤了虚拟旅商（NPC #n）`
3. 点击旅商 → 正常对话（**需点击一次**，见下方限制说明）
4. 关闭对话 → 旅商消失，日志 `[ShopUI] 玩家 xxx 已断开对话…移除虚拟旅商`
5. 再挥动锡斧 → 旅商出现在脚底；挥动第二次 → 拉回身边

## 实现原理（1.4.5 / TShock 6.1.0 源码实证）

### 仅自己可见（核心）
- 服务器创建**真实**旅商 NPC（368），但出站包经 **MonoMod detour `NetMessage.SendPacket`** 定向过滤：
  - `23 号包 SyncNPC`：body 前 2 字节 = NPC 索引，匹配虚拟旅商且接收者≠所属玩家 → **跳过**
  - `40 号包 SyncTalkNPC`：body 中 talkNPC 匹配虚拟旅商且接收者≠所属玩家 → **跳过**
- 其他玩家客户端收不到该 NPC 的任何包 → 实体不存在 → 完全不可见、无法交互
- 玩家重新进入旅商所在区域时，`SyncNPCsForSection` 的 23 号包同样被过滤 → 不泄漏

### 挥动检测
- `GetDataHandlers.PlayerUpdate`（TShock 已解析 13 号 PlayerControls 包）
- `Control.IsUsingItem` **false→true 上升沿** + 手持槽位物品 `== 3500`

### 对话与移除
- **绝不主动发 40 号包**：40 号包只同步 talkNPC 状态、不携带对话文本，主动发送会把客户端 talkNPC
  卡在虚拟旅商上（与残留 npcChatText 组合出**虚假对话窗口**，且 `mouseInterface` 被占用 →
  玩家点击正常 NPC 失效）。对话状态完全由客户端点击旅商自然建立
- 客户端点击旅商 → 对话正常打开；关闭对话自动上报 40 包 `talkNPC=-1` → OTAPI 底层钩子检测 → 移除
- **精确区分对话对象**：仅当"关闭的是旅商对话"才移除——玩家先点了向导/商人等 NPC 再关闭，不会误移除旅商
- 移除 = `life=0 + active=false` + 定向广播 23（客户端 `num219<=0 → active=false`）

### 注意：40 号包不能"强制弹出"对话面板
`40 号包` 只同步 talkNPC 状态，客户端对话面板显示依赖 `npcChatText != ""`，而该文本只能由
客户端点击 NPC 时 `GetChat()` 填充 —— **服务端无法仅靠协议包强制弹出对话**，玩家需点击一次旅商。

## 已知限制

- 对话面板需玩家点击旅商后打开（无法服务端强制弹出）
- 服务器端存在真实 NPC 实体（对其他系统如 NPC 计数有轻微影响，后续可优化为纯虚拟）
- 旅商站定不动（`aiStyle=-1`）
