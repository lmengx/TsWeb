# ItemFlash 掉落物献祭插件

> TShock 子插件（TShock 6.1.0 / Terraria 1.4.5.6 / net9.0）
> 玩家把指定物品丢在一起 → 判定成功 → 主角物品做动画后消失。

## 功能

- **组合判定**：检测服务端掉落物，玩家把配方所需物品丢在同一区域（默认 5 格内）即判定成功
- **来源过滤**：只认玩家丢出的物品（通过 `GetDataHandlers.ItemDrop` 登记），NPC 掉落物不参与，避免误触发
- **两种动画模式**：
  - `simple`：主角物品升空 1 秒后消失，其他材料静默消耗（土块献祭）
  - `zenith`：**天顶剑仪式**——10 把剑升空聚拢 → 核心剑（铜短剑）移入中央持续被雷劈 + 闪光粒子 → 其它 9 把剑依次飞入中心（效果逐渐增强）→ 只剩铜短剑续劈 3 秒粒子爆发 → 中心生成一把天顶剑
- **可配置配方**：JSON 配置文件，支持多配方，`/reload` 热重载

## 默认配方

| 配方 | 材料 | 结果 |
|------|------|------|
| 天顶剑合成（zenith） | 泰拉刃 + 彩虹猫之刃 + 狂星之怒 + 波涌之刃 + 南瓜剑 + 种子弯刀 + 星怒 + 养蜂人 + 附魔剑 + 铜短剑（10 把剑丢在一起） | 天顶剑 ×1 |
| 土块献祭（simple） | 1 土块 + 2 金币 | 无 |

## 安装

1. `dotnet build` 编译（TShock 6.1.0 官方 NuGet 包）
2. 将 `ItemFlash.dll` 放入服务器的 `ServerPlugins/`
3. 重启服务器（或热重载）
4. 首次运行自动生成配置 `{TShock.SavePath}/ItemFlash/config.json`

## 配置（config.json）

```json
{
  "enabled": true,
  "clusterRange": 80,
  "recordWindowSeconds": 60,
  "recipes": [
    {
      "name": "土块献祭",
      "items": [
        { "itemId": 2, "count": 1 },
        { "itemId": 73, "count": 2 }
      ],
      "animateItemId": 2,
      "message": "献祭成功！土块带着金币升天啦"
    }
  ]
}
```

| 字段 | 说明 |
|------|------|
| `enabled` | 总开关 |
| `clusterRange` | 聚类判定距离（像素，1 格 = 16px；默认 80 ≈ 5 格） |
| `recordWindowSeconds` | 玩家丢物记录有效期（秒）。超过此时长的丢物记录不再参与判定 |
| `recipes[].name` | 配方名（日志用） |
| `recipes[].items` | 所需材料组合，`itemId` 物品 ID（2=土块，73=金币，4956=天顶剑），`count` 所需数量（按掉落物 stack 累计） |
| `recipes[].animation` | 动画模式：`simple`（默认，主角升空消失）/ `zenith`（天顶剑仪式） |
| `recipes[].animateItemId` | 做动画的主角物品 ID（仅 simple 模式，必须出现在 items 中，不填则取 items[0]） |
| `recipes[].resultItemId` | 动画结束生成的结果物品 ID（0 = 不生成；天顶剑 = 4956） |
| `recipes[].resultCount` | 结果物品数量 |
| `recipes[].message` | 触发成功的玩家提示，空字符串则不提示 |

**匹配规则**：判定以**玩家丢物记录**为准（不依赖掉落物静止状态，传送带/液体上也能判定）。同一玩家在 5 格内丢出的物品累计数量 ≥ 配方所需即满足；地上残留的其他物品不影响判定。判定后按配方所需**精确扣减**（如配方需 2 金币，区域有 3 金币只扣 2，多余的保留，不会误耗 NPC 掉落）。主角物品（土块）整体做动画消失。

## 判定与动画原理

### 检测
- 玩家丢物品 → 客户端发 **21 号包（ItemDrop）** → TShock `GetDataHandlers.ItemDrop` 事件 → 登记（玩家/类型/位置/时间），不拦截
- 每 10 tick（约 0.17 秒）扫描 `Main.item[]`（服务端权威掉落物表）：
  1. 过滤"落地静止"的掉落物（velocity < 1）
  2. 匹配丢物登记（同类型、时间窗内、位置 6 格内）→ 关联到丢它的玩家
  3. 按玩家分组 → 空间贪心聚类（距离 ≤ clusterRange）→ 配方比对

### 动画
- **防捡**：`keepTime = 600`（掉落物 `FindOwner` 在 keepTime>0 时直接返回，玩家无法拾取）
- **升空**：每帧由服务端直接控制 `position` 线性抬升（不依赖物理），每 3 帧广播一次 21 号包同步位置
- **粒子**：每 10 帧广播一次 **82 号 NetModule 粒子包**（`ItemTransfer` 金色特效）。服务端广播直接写 socket、不经 `NetManager.Read`，不受主插件 ParticleGuard 防线拦截
- **消失**：`TurnToAir()`（type=0）+ 广播 21 号包 → 客户端 `SetDefaults(0)` → `active=false` → 掉落物消失（协议实证：`Item.active => type != 0`）

## 测试指令

- `/iflash`（权限 `tshock.admin`）：在命令者脚下生成 10 把天顶剑材料掉落物并**直接触发仪式动画**（绕过判定逻辑）——用于排查判定问题/验收动画效果。触发后服务器日志会输出 `[ItemFlash] 测试指令触发天顶剑仪式`

## 版本历史

- **v1.4.7**：性能优化——无丢物登记时早退（不再每轮全遍历）；每轮扫描只收集一次掉落物快照供所有簇复用（N 簇 N 次遍历 → 1 次）；动画槽位改用 `HashSet` O(1) 查询（替代遍历会话列表）；动画结束及时释放槽位登记
- **v1.4.1**：修复核心剑在飞入阶段掉地（case 2 每帧钉位置）；雷击整体加密（蓄力 25t/飞入 18t/终局 20t→8t 加速）；每把剑飞入中心时追加微光+重铸金光特效；飞入间隔改 1 秒 1 把
- **v1.4.0**：核心剑修正为铜短剑（配置迁移 v3）；动画期间广播 21 号包 `number2=2` 使客户端持续保持 keepTime，彻底禁止拾取拉取（防吸附）；整体进度放慢（聚拢 1.25s/蓄力 2.5s/飞入间隔 0.6s/终局 4s）；飞入阶段其它剑继续环绕不落地；终局微光炼化（ShimmerTownNPC）+ 哥布林工匠重铸特效（BestReforge），生成**传奇（Legendary）词缀**天顶剑
- **v1.3.0**：天顶剑动画重构。核心剑（铜短剑，由 `animateItemId` 指定）移入中央持续被雷劈；其它 9 把依次飞入中心，雷击与闪光粒子随进行逐渐增强；只剩核心剑后续劈 3 秒粒子爆发，最后炼化生成天顶剑；移除全部调试日志
- **v1.2.3**：修复配置迁移失效（`Version` 默认值 bug 导致旧配置永远不补天顶剑配方）；判定链路加调试日志定位
- **v1.2.2**：配置版本迁移（旧配置自动补天顶剑配方）；判定调试日志；GameUpdate 异常防护
- **v1.2.1**：新增测试指令 `/iflash`（tshock.admin），脚下生成材料直接触发天顶剑仪式，绕过判定便于排查
- **v1.2.0**：新增天顶剑仪式（zenith 动画）。10 把材料剑升空聚拢→环绕旋转→轮流飞出（每把雷击）→中心生成天顶剑；配方新增 `animation`/`resultItemId`/`resultCount` 字段；默认配方改为天顶剑合成 + 土块献祭
- **v1.1.0**：修复判定不稳定。判定改为"记录驱动"：以玩家丢物记录聚类（不再要求掉落物静止、不再要求区域类型纯净），区域验证 + 精确扣减（不误耗 NPC 掉落），丢物登记有效期 60→120 秒，触发后清空该玩家登记防重复触发
- **v1.0.0**：首个版本。玩家丢物登记 + 轮询聚类匹配 + 主角升空动画 + ItemTransfer 粒子 + keepTime 防捡 + 21 号包消失同步；JSON 多配方配置，`/reload` 热重载
